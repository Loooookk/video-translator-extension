# 视频实时翻译

将正在播放的视频语音或字幕翻译成中文。DeepSeek 负责文字翻译，Whisper 负责本机语音识别。更换 DeepSeek 模型不会直接提高收音或语音识别的准确率。

## 安装和更新

1. 在 Chrome、Edge 或 Yandex 桌面浏览器的扩展管理页开启开发者模式。
2. 使用“加载解压缩的扩展”选择本文件夹。音频模式要求 Chromium 116 或更新版本。
3. 更新代码后，在扩展管理页点击本扩展的重新加载按钮，再刷新视频网页。
4. 打开播放器声音和字幕，点击扩展图标后开始翻译。

Safari 只能使用字幕模式。可用 `npm run safari` 生成 Xcode 工程，再通过 Xcode 签名安装。

## 推荐设置

- 有原字幕：选择“自动”或“字幕识别”。原字幕比重新识别声音更可靠，WebVTT 字幕会提前翻译后续两条。
- 日语：选择原语言“日语”、语音模型“base”。英语同理，选择“英语”。
- 多种语言混合：原语言选择“自动识别”。
- “tiny”更省资源；“small”通常更适合追求识别质量，但下载和推理更慢。已有设置会保留，不会自动把 tiny 改为 base。
- 翻译接口选择 DeepSeek，填写自己的 API Key。默认使用 V4 Flash，关闭思考并流式输出；也可选择 V4 Pro。

DeepSeek 的模型名称及非思考、流式参数依据 [官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。API 调用由服务提供商按账号用量收费。此项目不包含 API Key。

## 本次修复

- DeepSeek 不再被 1.1 秒超时提前取消。收到译文片段就更新，超时覆盖完整响应体；密钥、余额、限流和网络错误会明确显示。
- 选择 DeepSeek 时不会悄悄改用其他翻译服务，也不会把原文伪装成完成的中文翻译。
- 取消短句和文本相似度误删，保留“はい”“No”、否定、数字和正常括号内容。
- 语音按照停顿分段。每约 0.8 秒尝试识别当前增长中的语句，后续结果可以修正前面的不完整句子，最长窗口为 8 秒。
- 修复语音库未指定语言时默认英语的问题：在同一次解码中选择语言 token，再继续原语言转写，不再额外跑一遍语言检测。支持指定原语言；模型切换会真正生效。
- 收到捕获流就建立声音回放，先恢复声音再加载模型。取消强制静音定时器，避免停止后误操作声音。
- 每次运行使用独立会话标识，防止旧识别结果、旧翻译和停止通知影响新会话。
- 字幕按当前 cue 和顺序更新，停止、字幕空档及切换视频时清理旧结果。同屏多行字幕不会只保留最后一行。
- 跨 iframe 汇总视频信息，按主要播放视频路由。支持 WebVTT，以及 YouTube、Bilibili、Video.js 已经渲染到页面的常见字幕节点。

## 同一网页有多个视频或广告声音

开始前可以在弹窗的“翻译目标”中指定视频，或自动选择可见面积最大的播放视频。开始后锁定该视频，不会因后来出现更大的广告播放器而切换。目标被移除时停止当前翻译，避免接着识别广告。

音频模式默认开启“临时静音其他播放器”，包括页面及可访问 iframe 内的其他 video/audio 元素、新插入的播放器。停止后恢复它们原来的静音状态；也可关闭声音隔离。字幕模式只读取所选主视频的字幕。

这不是广告拦截器。同一个播放器内插播的广告，以及绕过 video/audio 元素直接使用 Web Audio 发声的广告，仍可能混入音频，需要具体网站适配。浏览器的 [tabCapture](https://developer.chrome.com/docs/extensions/reference/api/tabCapture) 捕获整个标签页，此处通过临时静音其他媒体元素减少混音。

## 延迟与准确率

0.8 秒是首次音频窗口长度，不是“完整中文翻译已经完成”的时间。音频模式总延迟还包括本地模型推理、排队、网络及 DeepSeek 生成，不能保证多语言全部在 1 秒以内准确完成。流式的第一版文字会随上下文修正。

有可读取的 WebVTT 字幕时，预翻译成功后可在对应字幕出现时直接读取缓存，减少网络等待。实时网页字幕只能读取已经显示的文字，首条字幕或提前翻译失败的条目仍需等待接口。

页面日志会显示语音识别耗时、翻译首字耗时、音频片段末尾到首字的估算时间。首次模型下载不计入稳定运行性能。推理或接口持续跟不上语速时，队列有上限，界面会提示已跳过过期音频或文字，避免延迟无限累积。

## 排查无字幕

1. 更新扩展后同时刷新视频页面，避免网页仍运行旧内容脚本。
2. 在播放器开启声音。页面提示模型加载时，等待下载完成。
3. 日语或英语不稳时指定原语言，避免短片段自动识别出错。
4. 字幕模式需要真实字幕；YouTube、Bilibili 等需要在播放器中开启字幕。没有字幕时手动切换音频模式。
5. 出现 Key 无效、余额不足、限流或网络错误时，按具体提示处理。

Whisper 小模型对音乐、噪声、多人同时讲话或极短片段仍可能误识别。这里的音量检测不是能严格区分音乐和说话的神经网络 VAD。浏览器捕获的是整个标签页的混音，广告声音也可能影响识别。DRM、受限页面、关闭的 Shadow DOM 和系统原生视频全屏可能限制声音或字幕访问。

## 开发与检查

```sh
npm install
npm run vendor
npm run check
npm test
```

`npm run check` 检查清单、脚本语法、资源引用和图标。`npm test` 使用模拟网络与浏览器环境，覆盖流式分包、超时、错误码、取消、缓存、音频分段、字幕顺序、会话切换和提前翻译。它不代表已通过真实浏览器收音或真实 DeepSeek 接口的准确率与延迟验收。

`npm run test:asr -- --download` 会下载或复用 Whisper base 模型，并用项目内英文、日文、俄文 WAV 做实际的自动语言识别测试。后续可用 `npm run test:asr` 仅使用缓存，或传入 `small` 选择其他模型。此测试使用 Node CPU 后端，输出识别文字及耗时；它检查语言判断和非空输出，不把它们等同于文字完全准确，也不代表浏览器 WASM 的性能。

本地测试页位于 `test/test-page.html` 和 `test/test-audio.html`，可在本目录运行 `python3 -m http.server 8123` 后访问。

## 隐私

音频在本机通过 Whisper 处理，不上传音频。选择 DeepSeek 时，当前识别文本和至多两段近期原文上下文会发送给 DeepSeek；选择免费自动接口时，文字会发送给 Google，已知源语言时还可能发送给 MyMemory。Key 存在扩展本地存储中。模型首次从 hf-mirror.com 下载，缓存后复用。

后台和离屏捕获方式参考 [Chrome 官方文档](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture)。
